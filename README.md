# StudyPredict — Student Performance and Learning Platform

Flask application for exploring student performance estimates, building a study routine, and playing a short educational quiz. The bundled model and CSV are **synthetic demonstrations**. This application is not validated for real student assessment or consequential decisions.

## Features

- Account registration and login with Werkzeug password hashing and Flask sessions.
- Protected student dashboard, input validation, habit recommendations, timetable, charts, and PDF report.
- Separate home, subjects, materials, recommendations, game, progress, profile, and model-insights pages.
- Brain Boost Challenge with five configurable questions, timer, explanations, increasing difficulty, and saved attempt history.
- SQLite persistence for accounts, game attempts, and material bookmarks.
- Model evaluation against a mean baseline with MAE, RMSE, R², and feature importance.

## Stack and architecture

- Python 3, Flask, SQLite, NumPy, pandas, scikit-learn, ReportLab.
- `app.py`: routes, sessions, authentication, APIs, report export.
- `templates/`: dashboard, auth, and learning pages.
- `static/`: styles, dashboard scripts, game script.
- `data/students.csv`: 1,500 synthetic examples; not an external academic dataset.
- `data/platform.db`: created automatically for local accounts and game records.
- `train_model.py`: deterministic training and holdout evaluation.
- `model/model.pkl`, `model/metrics.json`: generated model artifact and evaluation output.

## Run locally

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env  # set a private SECRET_KEY before deployment
python train_model.py
python app.py
```

Open <http://127.0.0.1:5002>, register an account, and sign in. `SECRET_KEY` should be a long random value in production. The development fallback in `app.py` is not suitable for deployment. For production, serve behind HTTPS and set `SESSION_COOKIE_SECURE=1` in the deployment configuration (cookie security configuration should be completed before public deployment).

## Model and data

The task is regression: estimate `final_score` from `study_hours`, `sleep_hours`, `screen_time`, `sports_hours`, `other_activities`, `attendance`, and `previous_marks`. The CSV has 1,500 rows, eight numeric columns, no missing values, and no duplicate rows. Its target is generated by a hand-authored formula with noise in `train_model.py`; it is not measured student data. The repository does not identify an external data source or license, so none is claimed. Do not use this dataset or its metrics to make claims about student outcomes. Replace it only with an appropriately licensed and documented real dataset before research or operational use.

The training script uses a deterministic 80/20 split and reports MAE, RMSE, and R² against a train-mean baseline. Current `model/metrics.json` results describe only this synthetic holdout. The displayed success probability is a score-gap heuristic, not a calibrated probability or uncertainty estimate. Feature importance describes model behavior, not causes.

There is no automated test suite yet.

## Current scope and limitations

The app currently persists users and Brain Boost scores/bookmarks. It does not yet support recording assessments, real subject marks, attendance history, teacher/admin accounts, teacher uploads, per-student prediction histories, notifications, or downloadable CSV reports. The subject/material pages clearly identify the lack of configured real marks or materials. Learning recommendations remain general until assessment records are supported. No external dataset was downloaded, and no paid AI service is required.
